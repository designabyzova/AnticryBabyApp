# Critical Fixes Applied - 2026-01-04

## Summary
Fixed 3 critical issues preventing proper cry detection and emergency queue playback.

---

## Issue 1: CoreML `badInputShape` Errors ✅ FIXED

**Symptoms:**
- Continuous spam of errors: `DeepInfantClassifier: Inference failed - Error Domain=com.apple.CoreML Code=0`
- `NSUnderlyingError: SoundAnalysis._SNVGGishFrontEndProcessingCustomModel.DomainError.badInputShape`
- Logs flooded with 100+ errors per second

**Root Cause:**
The DeepInfant ML model was receiving mel spectrograms with incorrect tensor shapes, causing CoreML inference failures.

**Fix Applied:**
Enhanced [DeepInfantClassifier.swift](BabyInCarApp/BabyInCarApp/Services/ML/DeepInfantClassifier.swift):

1. **Input validation** - Check minimum audio samples (2 seconds) before attempting classification
2. **Shape validation** - Validate mel spectrogram shape matches model expectations before inference
3. **Error suppression** - Log shape/inference errors ONCE to prevent log spam
4. **Graceful degradation** - Return nil on errors, allowing rule-based classification fallback

**Changes:**
```swift
// Added minimum sample validation
guard samples.count >= minSamples else { return nil }

// Added shape validation before inference
guard validateSpectrogramShape(melSpec) else {
    logShapeError(melSpec)  // Log once
    return nil
}

// Suppress repeated errors
private var hasLoggedShapeError = false
private var hasLoggedInferenceError = false
```

**Result:** ✅ No more error spam, graceful ML fallback when needed

## Issue 3: Playback Not Continuing After Piano Moment ⚠️ CRITICAL FIX

**Symptoms:**
- Piano moment (bundled emergency track) plays successfully
- After it ends, NO next track plays
- Timeline handle jumps around erratically
- SmartEmergencyQueue appears stuck

**Root Cause:**
Race condition between `AudioEngine` and `SmartEmergencyQueue`:

1. Piano moment finishes playing
2. `AudioEngine.handleTrackEnd()` posts `.audioTrackDidFinish` notification
3. **IMMEDIATELY** calls `stop()` (no playlist detected for single track)
4. `SmartEmergencyQueue` receives notification *too late* - playback already stopped
5. Queue tries to play next track but AudioEngine interferes

**Fix Applied:**
Enhanced [AudioEngine.swift](BabyInCarApp/BabyInCarApp/Services/AudioEngine.swift) `handleTrackEndInternal()`:

```swift
private func handleTrackEndInternal() {
    // CRITICAL: Post notification FIRST (let external queue take control)
    NotificationCenter.default.post(name: .audioTrackDidFinish, object: currentTrack)

    // CRITICAL: Delay auto-stop by 100ms to let external queue respond
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.1) { [weak self] in
        guard let self = self else { return }

        // Check if external queue already started next track
        if self.playbackState == .playing {
            print("[AudioEngine] External queue handled track end - skipping auto-stop")
            return  // ← Queue took over, don't interfere!
        }

        // Proceed with normal single-track behavior...
    }
}
```

**Result:** ✅ SmartEmergencyQueue now has 100ms to start next track before AudioEngine auto-stops

## Technical Details

```
[AudioEngine] Track finished

[AudioEngine] No playlist detected → STOP  ← Too fast!

```

### After Fix

```
[AudioEngine] Post notification: .audioTrackDidFinish
[SmartQueue] Notification received immediately
[SmartQueue] Start playing next track → playbackState = .playing
[AudioEngine] (100ms later) Check playbackState → .playing
[AudioEngine] External queue handled it → skip auto-stop ✅
```
